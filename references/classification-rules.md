## 差评判定（最高优先级）
- 唯一标准：评价正文**确实表达不好**才算差评。与星级、是否带图无关。
- 以下措辞**不是**差评："漏斗"等名词、"担心破损"（收到完好）、"故障率低"、"坏了就买非常好"、"没有一次打印失败"、"后悔没早买"、期待/许愿式建议。
- 建议与抱怨区分："希望增加XX功能"若整体满意，不算差评；明确表达不满、故障、推诿、失望才算。
- 流程：关键词初筛 → 逐条人工阅读全文复核 → 最终差评清单。复核记录保留原因。

## 差评归因分层（多标签）
一条差评只要符合描述即可同时归入多类（如故障+售后不处理 = defect+service）。

| key | 类型 | 判定 | 营销价值 |
|---|---|---|---|
| defect | 硬缺陷型 | 产品质量、功能故障 | 高频立刻解决；低频偶发属品控概率，价值不大 |
| service | 服务型 | 物流慢、客服态度差、售后不处理 | 同上，常与 defect 伴生 |
| expect | 预期不符型 | 产品没问题但和用户想的不一样 | 最有价值：详情页前置真实信息 |
| scene | 场景错配型 | 买错了、不会用导致体验差 | 明确"适合/不适合"，前置使用边界 |

- 归因结果写入 `negtype_map`：`"平台key|YYYY-MM-DD": ["defect","service"]`；未映射的差评默认 defect。
- 四类若在竞品评价中高频出现且我方能规避，即为可对标的核心打击点。

## 好评语言素材（画面感口径）
- 只要**有画面感、精确**的表达，可直接帮助营销图片/视频创作。合格示例："无牙仔的翅膀纹理和冰淇淋的螺旋纹路都特别清晰"。
- 不合格：关键词罗列、笼统夸赞（"精度高/细节清晰/操作简单/很满意"）、模板化好评、AI 代写腔。
- 入选条件（生成器默认实现，可按品类调词表）：具体物象/可视场景强标记命中；或弱标记（锅数、肉眼等）组合出现；并命中至少一个素材分类。
- 高亮仅三类：画面场景（hl-scene）、比喻（hl-metaphor）、精确数据（hl-vocab），不高亮通用形容词。
- 候选必须人工终审，宁可少而精。

## 好评动因拆分与竞品校准
- 标配型 std：全行业默认该有的点，夸得再多也不是优势。
- 增益型 gain：超预期、主动提及且竞品少见的点 = 差异化卖点。
- 决策验证型 verify：下单前顾虑、收货后专门验证并夸赞 = 转化杀器，原话可原封不动用于详情页/主图/直播间，不要泛化改写。
- 一条好评可含多个动因；频率统计按"提及该动因的好评数"。
- 竞品对比必须用**同一套文本关键词口径**（TEXT_POINTS）统计双方；默认校准规则：竞品提及率 ≥ 我方 70% 或 ≥ 15% 建议降为标配；竞品 0 提及为强差异化；其余差异化保留。
- 报告须注明：竞品提及率为 0 不代表竞品没有该功能，仅表示其买家未主动提及。

## 场景 / 人群 / 象限推断
- 场景与人群均为**多标签文本推断**，基于全部评价（含差评），占比按总评价数计；报告注明"推断"属性。
- 核心主流场景做透；小众高价值场景做长尾；某人群好评占比高且满意强时，从泛人群收缩到精准人群语境。
- 象限：横轴=用户提及频次，纵轴=优势判读（分析判断，非精确测量）；每个标签可点击筛选对应评价。

## 评价展示硬性要求
- 带图评价必须把自己的文字与图片放在同一卡片，不得拆成独立画廊。
- 每条评价最多展示 6 张图，原始完整图片统计以 stats JSON 为准；大图用平台大图地址（如京东去掉 `s300x300_` 前缀）。
- 页面结构：三目标卡片（红=差评止损、绿=好评增效、蓝=洞察增收）在卖点分布上方；固定区域一次只显示一个目标模块，默认差评止损；好评与洞察内部用子标签切换。
- 选中态用上浮阴影+底部指示条+徽章，不用黑色边框。
